# 2026-06-24 工作日志

## 前后端分离重构——业务逻辑迁移至后端

### 背景
将项目中所有业务逻辑从前端（Next.js）迁移至后端（FastAPI），确保前端仅负责 UI 渲染与用户交互，所有数据处理、验证、计算及业务规则均由后端 API 统一处理。

### 新增文件
- `backend/services/compute.py` — 纯计算服务层，包含所有业务逻辑函数（数据提取、校验、汇总、趋势分析、地域/店铺聚合、日期工具、合并等）
- `backend/routers/compute.py` — 计算 API 路由层（29 个端点），thin controllers 调用 services/compute.py

### 修改的核心文件

**后端：**
- `backend/main.py` — 注册 compute router

**前端 API 层：**
- `src/lib/api.ts` — 新增所有 compute API endpoints 的客户端函数
- `src/lib/compute-service.ts` — 重构为 async API wrappers，所有函数委托给后端
- `src/lib/records-service.ts` — mergeRecords 改为调用后端 API
- `src/lib/store.ts` — 更新 re-exports 以适配新模块结构

**前端组件（全部重写）：**
- `src/components/day-overview.tsx` — 所有聚合计算改用 API（computeFilteredSummary、computeOptions）
- `src/components/weekly-trend-chart.tsx` — 趋势数据、产品选项等全部改用 API
- `src/components/product-analysis.tsx` — 产品分析聚合调用 API
- `src/components/region-distribution.tsx` — 地域聚合/趋势改用 API
- `src/components/shop-distribution.tsx` — 店铺聚合/趋势改用 API
- `src/components/data-import-dialog.tsx` — JSON 解析/数据校验改用 API
- `src/app/page.tsx` — merge/global stats 改用 API

### Bug 修复
- `backend/services/keyword_rules.py` — 修复 `\\` 行继续语法错误（改为单行调用链）
- `backend/services/rules_import.py` — 修复 ISO-8859 编码问题（重写为 ASCII-safe）

### 架构原则
- 前端不再包含任何业务逻辑计算
- 所有计算通过 POST API 发送数据 + params，后端返回结果
- localStorage 仍用于客户端持久化
- 后端 compute router 共 29 个端点，覆盖所有业务场景
